# B2a — Exercise Instructions Data Foundation — design spec

**Status: DESIGN APPROVED (2026-06-06).** Ready for an implementation plan.
First of three B2 sub-projects (**B2a data → B2b detail component + in-workout
popup → B2c browse page + filters**). Folds under **R-27 (Project B)** — no new
R-id/D-id.

Follows **Project B1** (`2026-06-04-catalog-ingestion-project-b1-design.md`),
which ingested 873 exercises with bilingual names, fine muscle tags, equipment,
images, and metadata — but **deferred instructions** ("present in source, deferred
to B2 — not imported in B1", `build-seed.ts:22`). This sub-project lands the
instruction data + the image-URL helper so B2b's `ExerciseDetail` component has
content to render. **No UI ships in B2a.**

---

## 1. Goal

Give every free-exercise-db exercise its **bilingual step-by-step instructions**
(English from source + machine-translated Spanish) in the DB, and a pure helper
that turns the stored relative image paths into CDN URLs. After B2a, the data
needed by the B2b detail view exists and is verified; nothing user-facing changes.

## 2. Scope

**In scope**
- New columns `instructions_en text[]` and `instructions_es text[]` on
  `public.exercises`.
- Ingest English instructions from the SHA-pinned `exercises.json` (already
  vendored in `scripts/exercise-catalog/`).
- A committed `es-instructions.json` of machine-translated Spanish steps,
  generated by an agent translation workflow (mirrors `es-names.json`).
- `build-seed.ts` extended to emit both instruction arrays; seed regenerated.
- A `source`-guarded backfill migration for already-seeded envs.
- `buildExerciseImageUrl()` pure helper (jsDelivr + `PINNED_SHA`).
- Regenerated `src/types/database.ts` (currently stale).
- pgTAP + Tier-1 unit tests.

**Out of scope (later sub-projects / deferred)**
- The `ExerciseDetail` component, image rendering, the in-workout popup → **B2b**.
- The `/exercises` browse page, filters, search, alias map → **B2c**.
- Human review of the machine-translated Spanish (accepted machine-only, per the
  same call as the B1 names).
- Instructions for the 34 hand-tagged **system** exercises — they have no source
  instructions; their arrays stay empty (B2b shows "no instructions yet").

## 3. Data model

Two parallel text-array columns on `public.exercises`:

| column | type | default | meaning |
|---|---|---|---|
| `instructions_en` | `text[]` | `'{}'` | ordered English steps (from source) |
| `instructions_es` | `text[]` | `'{}'` | ordered Spanish steps (machine-translated) |

- **Parallel arrays, index-aligned:** `instructions_es[i]` is the translation of
  `instructions_en[i]`; the two arrays have equal length per exercise. (Rendering
  picks the array by language with EN fallback, mirroring `exerciseDisplayName`.)
- Both default to empty `'{}'` so the 34 system rows and any future manual rows
  are valid without instructions.
- No validation trigger needed (free-text content); integrity is enforced at
  **build time** (see §5) and asserted in pgTAP.

> Why two array columns rather than a JSON blob or a child table: it matches the
> existing `name_es`/`name_en` + `primary_muscles[]`/`secondary_muscles[]` shape,
> needs no joins, and the steps are a simple ordered list with no per-step
> metadata. YAGNI on a child table.

## 4. Ingest pipeline (extends `scripts/exercise-catalog/`)

The B1 pipeline already reads the SHA-pinned `exercises.json` and emits an
idempotent seed. B2a extends it:

1. **English** — `RawExercise.instructions` already exists in the source data
   (`build-seed.ts:22`). `buildRow` emits it as `instructions_en`.
2. **Spanish** — a new committed file `scripts/exercise-catalog/es-instructions.json`
   shaped `{ "<external_id>": ["<paso 1>", "<paso 2>", …] }`. `build-seed.ts`
   reads it (like `es-names.json`) and emits `instructions_es`.
3. **Generation** — `es-instructions.json` is produced by a one-off **agent
   translation workflow** (dev-time, NOT in CI), batching the 873 exercises'
   step arrays through translation subagents (the B1 names used an 18-agent
   workflow; instructions are longer, so batch by exercise with each subagent
   returning a `{external_id: es_steps[]}` map). The workflow is a dev artifact;
   only its **output JSON is committed**.

The image relative paths are already stored (`images text[]`, B1); B2a only adds
the **URL helper** that consumes them.

## 5. Build-time integrity (in `build-seed.ts`, unit-tested)

`build-seed.ts` fails the build (so CI/`exercises:build` catches drift) when:
- an `es-instructions.json` key is not a known `external_id` (stale entry), or
- for any exercise, `instructions_es.length !== instructions_en.length`
  (mis-aligned translation), unless **both are empty** (the system/no-source
  case is allowed).

This is the same "build fails on stale/invalid override" guarantee B1 gives for
`primary-overrides.json`.

## 6. Seed regeneration + backfill (mirrors B1 / #160)

- **Schema migration** `20260606120300_b2a_instructions_columns.sql` — adds the
  two columns (`add column if not exists … default '{}'`). Idempotent. (Sorts
  after the catalog migrations `…120000/120100/120200` already on this date.)
- **Regenerated seed** (`20260604120200_b1_catalog_seed.sql`) — UNCHANGED in
  structure (option B, resolved at plan time). The seed is dated 2026-06-04 and
  on a fresh `db reset` runs BEFORE the 2026-06-06 columns migration, so it
  cannot reference the instruction columns. The backfill (below) is the SINGLE
  populator for both fresh and already-seeded envs; the seed's INSERT/SELECT/
  conflict clause does not carry instructions. (Re-dating the seed to 2026-06-06
  was rejected: it would reorder it past the three 2026-06-06 review migrations
  that depend on the seed rows existing.) The regenerated seed's only diff is its
  provenance comment line.
- **Backfill migration** `20260606120400_b2a_instructions_backfill.sql` — for
  envs where the B1 seed already ran (e.g. production), a set-based UPDATE that
  writes `instructions_en`/`instructions_es` from a `(external_id, en, es)`
  VALUES list, guarded `source = 'free-exercise-db'`, idempotent. (Generated by
  the same `exercises:build` run, like the #160 review migration.)

> Open call resolved (option B): the backfill migration is the SINGLE populator
> for BOTH fresh/dev and already-seeded envs (it sorts after the columns
> migration on every `db reset`); the seed stays instruction-free at its
> 2026-06-04 timestamp. The backfill and the regenerated seed both come out of
> one deterministic `exercises:build`, so they can never disagree.

## 7. Image-URL helper

`src/features/training/exercises/images.ts` (new):

```ts
// free-exercise-db images, served via jsDelivr at the SHA build-seed pins.
const SHA = 'b0eed061e1c832b3ed815fbaa4b45b3cdc14df49';
const BASE = `https://cdn.jsdelivr.net/gh/yuhonas/free-exercise-db@${SHA}/exercises`;

/** Build a CDN URL from a stored relative image path (e.g. "Bench_Press/0.jpg"). */
export function buildExerciseImageUrl(relativePath: string): string;
```

- Pure + unit-tested (path with/without leading slash, empty handling).
- The SHA is duplicated from `build-seed.ts`'s `PINNED_SHA` **intentionally**
  (the script is dev-only and not bundled into the app); a unit test asserts the
  two stay equal by reading the script's constant, so they can't drift silently.

## 8. Types

`src/types/database.ts` is **stale** — it predates B1, so it is already missing
`images`, `level`, `mechanic`, `force`, `category`, `external_id` as well as the
new instruction columns. Regenerate it from the local schema
(`supabase gen types …`) so the app compiles against the real table.

## 9. Verification

- `corepack pnpm lint` + `build` + `test` green; new Tier-1 tests:
  - `build-seed` emits `instructions_en`/`_es`; build fails on stale id /
    length mismatch.
  - `buildExerciseImageUrl` + the SHA-equality test.
- Local Supabase (`db reset` applies the columns migration + regenerated seed +
  backfill from zero; **Docker must be running**) + `supabase test db`:
  - new pgTAP asserts: both columns exist; a sampled `free-exercise-db` row has
    non-empty equal-length EN/ES; a `source='system'` row (one of the 34
    hand-tagged exercises) has empty instructions.
- CI `db-test` is the merge gate.
- PR → `develop`, squash auto-merge.
